01 · 개요 & 스택

피부과·미용 클리닉을 정기적으로 이용하는 20~40대 여성이 여러 병원에 흩어진 시술 기록·시술권·포인트·결제·주기를 한 곳에서 관리하는 개인용 앱. 경쟁(강남언니·굿닥)이 병원 마케팅 플랫폼이라면, Bloomlog는 사용자 중심 개인 관리 앱이다. 핵심 가치 = 쌓이는 시술 이력에 의한 락인(lock-in) + 익명 통계 데이터 자산.

상태 관리 — 2원화 (주의)

Context + 직접 supabase 호출 (주력)

  • RecordsContext — 시술 기록 CRUD + Bloom 단계 계산
  • CyclesContext — 주기 (Realtime 구독)
  • SeasonContext — 관리모드 4단계 (DB)
  • 컨텍스트 간 갱신은 window.dispatchEvent('skindesk:data-changed') 커스텀 이벤트로 강제 (안티패턴)

localStorage

  • ManagementSettingsContext — 부위별 관리강도 (tight/maintain/none)
  • skindesk_* 키 — 테마·온보딩·FAB 위치·탭 순서
  • bloomlog_saved_email/password — 로그인 기억
TanStack Query는 설치돼 있으나 실제 데이터 흐름의 대부분은 Context가 담당. 혼재 주의.

03 · 두 도메인 구조 ⭐

코드베이스는 사실상 두 시스템이 한 앱·한 DB에 공존한다. 이 경계 이해가 유지보수의 핵심이다.

도메인 A

개인 시술 기록 (사용자용 · 원래 핵심)

사용자가 자기 시술/결제/포인트/주기/진단을 기록·관리. 모든 행은 user_id로 RLS 분리.

도메인 B

클리닉 이벤트 카탈로그 ("Workstream B")

어드민이 카톡/SMS/배너 이미지를 AI 파싱해 클리닉 이벤트·시술 가격 DB를 구축, 사용자에게 노출. 검수 워크플로우 + 파싱 피드백 루프.

clinic_brandsclinic_locations clinic_eventsclinic_treatments package_optionsparse_corrections treatment_glossary
